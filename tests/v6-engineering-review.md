# V6 assembly and live browser verification

Verified 5 November 2026 against the local assembled site at `http://127.0.0.1:8766`. This is local verification, not a deployment or hosted-release claim. No requests were intercepted and no data fixtures were substituted in the new live suite.

## Assembled checkpoint

`tools/assemble.mjs` now includes `equipment.json` as `data.equipment` and `attack-matrices.json` as `data.matrices`. Existing spell alias union, shared-class access and shared source-page merging remain unchanged. Monsters and character generation remain outside this assembly/UI change.

The resulting `dist/data.json` contains:

- 638 spell entries with effect cards, 148 rule entries and three source books.
- 16 class guides, 1,040 level-change groups and 1,117 individual changes, matching the current author JSON exactly.
- 80 equipment entries: 45 source-listed prices and 35 explicit unknown prices.
- One partial fighter attack matrix: 210 cells, 70 known values and 140 nulls.

Effect-card availability does not imply exhaustive rules coverage or visual verification. Existing incomplete flags and extraction gaps are preserved. Zero and negative matrix targets remain numeric; nulls are never filled from a formula. Coin prices and gp-weight remain separate fields with their own sources.

The UA owner confirmed all four pending corrections before final assembly: Whip, Dolor, Dismissal and Irritation. The assembled regression compares their casting fields, effects, conditions, exceptions and verification metadata with the corrected author records. The verified `ua-spells.json` SHA256 is `6eb4d4a59d9b33448d61b8e923702673bd27c6611c617221499fd9d3675648c0`.

## Checks performed

- `node --test tests/*.test.mjs`: **66 passed**, zero failures. This includes the new equipment/matrix provenance tests and assembly regressions for the current classes, indexed spell IDs, aliases, shared cantrip access and the four UA corrections.
- Existing browser suites: **87 checks passed**—24 core, 24 search, 21 advancement and 18 spell-level toggles. No uncaught JavaScript errors.
- `TEST_URL=http://127.0.0.1:8766 node /tmp/adnd-review-gear-ui.cjs --live`: **66 checks passed**. The compatibility path is a symlink to the source-ready `tests/gear-matrix-browser.cjs`; direct execution of that source file is equivalent.
- Axe: **13 state scans, zero violations** for the selected WCAG 2 A/AA and WCAG 2.1 A/AA rules. Nine scans come from the existing accessibility suite and four cover gear/source-dialog and expanded matrix states.

The live suite verifies price filters, crossbow aliases and per-field source dialogs, browser-note escaping/persistence/return links, official AC0 transitions, the separately labeled fighter-only Alt and its DMG p.74 anchor, the separate optional natural-20 amendment, and internal matrix scrolling at mobile widths. Its palette regression covers both keyboard and mouse selection from another spell and from a class view at 320, 390 and 491 pixels. Every selection must place the selected article's heading within the viewport and give that heading focus; title/hash equality alone cannot pass. Reduced-motion navigation is separately checked at all three widths for immediate scrolling and visible focus.

Generated reports are in the ignored `test-results/` directory. The new suite writes `gear-matrix-browser-report.json`; the existing suites write their corresponding reports.

## Environment and boundaries

Port 8765 accepted connections but closed them before an HTTP response (`UND_ERR_SOCKET`), so all canonical checks used the dedicated local server on 8766. Axe-core was installed only under `/tmp/adnd-qa`, using a temporary npm cache. This did not add production dependencies.

No author JSON, app code, styles, source identity, Git commits, GitHub pushes or deployments were changed by this engineering task. `dist/data.json` was regenerated by the requested assembly. Source-table visual verification remains pending; these tests validate application behavior and source-data preservation rather than establishing the correctness of unverified OCR.
