# Quantity and source-absence detector proposal

The pre-repair candidate baseline is in [`quantity-source-absence-detector-baseline.json`](quantity-source-absence-detector-baseline.json). The private full candidate lists and bounded snippets remain outside the repository. This proposal does not change catalog records or assert that a printed source omits any quantity.

The follow-up tool should scan every scalar leaf in `dist/data.json` and the nine monetary row-identity audit inputs, recording each input hash, leaf denominator, JSON pointer, nearest owner/source identifiers, and bounded value hash. Its candidate universe should combine explicit uncertainty terms (`unspecified`, `not stated`, `unknown`, `unclear`, `unresolved`, `pending`, `missing`, and related forms) with quantity/unit/count/size/amount/time-context words in both field names and values. It should report two distinct denominators: all uncertainty candidates, and the monetary-input subset that also carries quantity/unit context. Null quantity-like fields belong in a separate inventory and never count as source-absence evidence.

Use distinct outcomes for (1) text that explicitly asserts a source quantity/unit/size/interval/count is absent, (2) extraction or review pending, (3) semantic/identity questions, (4) not assessable or evidence unavailable, (5) quantity-context uncertainty without an absence assertion, and (6) other uncertainty/workflow text. A source-absence label means only that a record makes the assertion; a human source review still has to decide whether it is true. A lexical no-match is not a pass.

The calibrated tests should include the existing Deck Gem assertion as a preserved detector hit; the UA Quarrels quantity assertion; an extraction-pending item that must not become an absence assertion; an unresolved semantic question; a source-unavailable case; the methodology statement that unreviewed pages remain unknown (must not become an item-level absence assertion); the null-quantity case (must not count as source absence); and a no-match fixture whose expected result is “not evaluated,” never “source quantity present.” A full-scan test should pin the complete scalar-leaf denominator and input hashes for a fixture snapshot, then show candidate and category counts. Every detector run should preserve pre-repair output so a future correction cannot erase its original finding.
