# Value-level verification log

`mechanics-audit-progress.json` is the durable audit snapshot. It inventories every included field of all 892 reference-bearing records and identifies the exact assembled-data version by SHA-256. Its denominator is the existing mechanics leaves selected in `tools/mechanics-audit.mjs`, including nulls and empty arrays; it is not a percentage of the books, all possible rules, or source-image coverage. Adding newly extracted fields changes that denominator.

Each field has its current value, status, reviewer identifier, and the record's inspected source pages and source-file hashes. `reviewRecords` preserves the original checked-value snapshots and proposed old/new values. Source-checked means a reviewer compared that assertion with the cited source; it does not certify completeness of the rule or resolve contradictory printing. Independent review of corrections is additionally recorded in each batch's review report.

Statuses separate unchecked values, source-checked assertions, proposed corrections, applied checked corrections, unextracted values, source conflicts, reviewed editorial advice, and stale evidence. An inspected percentage includes proposed corrections and editorial review; the source-checked percentage does not. Counts are not interchangeable.

Run `node tools/mechanics-audit.mjs --check` to validate the committed snapshot. Run `node tools/mechanics-audit.mjs --from-log` to rebuild using its embedded review evidence. During an active audit, running without flags imports local `research/mechanics-*.json` review files when present; those working files are excluded from Git. Newly changed values cannot silently inherit earlier checks: they require a recorded reviewed correction or re-review.

The equipment batch review is in `tests/mechanics-equipment-review.md`. Remaining audits continue in bounded batches; a field without completed evidence stays explicitly unchecked. Source-image availability alone never changes a field's verification status.

The [equipment completeness review](equipment-completeness-review.md) separately records the source areas searched for missing mechanics and remaining evidence limits. Completed value review of the current fields is distinct from exhaustive extraction of all book content. Accepted equipment and spell/class changes retain independent value snapshots in the regression fixtures; local working proposals are excluded from Git once their evidence is embedded in the durable log and fixtures.

Rewording an editorial status note does not make it source-checked mechanics. Likewise, an applied clarification does not clear a still-documented source conflict. The generator preserves those dispositions and rejects unreviewed changes even when a conflict flag is present.

An accepted correction to a parent list also cannot promote a retained `Gap:` note or null value into source-checked mechanics. See [remaining audit work](remaining-audit-work.md) for the distinction between available-source extraction, source-policy questions, and unfinished calculator features.
# Source completeness inventory

The separate source-completeness run starts at deployed commit `d0d3c0bf55607bdadd956aaa3f72fe9af53618ff`. Its [coverage report](source-completeness-coverage.md) and [JSON ledger](source-completeness-coverage.json) join five book inventories to the captured site inventory. They account for 776 physical PDF pages and one separate DMG p.175 image, with 559 overlapping named units/candidates. A complete semantic source-unit denominator is not established; no whole book is certified complete.

Each `source-completeness-{phb,dmg,ua,mm,mm2}.json` file preserves page mappings, named source scope, site dispositions, checked-negative boundaries and unassessed work. Physical-page screening, headings, table rows, creature profiles, source fields, rendered content and search projections are distinct denominators. The MM/MM2 catalogue is explicitly outside current searchable product scope; internal locator gaps remain separately recorded.

The [repair register](source-completeness-repairs.json) distinguishes runtime repairs from source-only transcription and pending work. Frozen before/after archives and independent reviews retain actual source/code identities and scoped failures. The [matrix detector](../tools/source-completeness-matrix-audit.mjs) catches three absent structured DMG p.74 tables in preserved before data; a shape or cell-count pass does not establish numeric source correctness. The source-transcription reviews independently compare all 378 missing matrix cells and their qualifiers.

Book-ledger dispositions and open-finding labels describe the frozen starting state. The aggregate report labels them as baseline findings and lists current repair batches separately. [Version 17 publication evidence](source-completeness-release-17-live.json) verifies PR #39, its exact merge, 28 selected asset bytes and 41 live browser checks; it does not certify the later matrix batch. The repair register identifies that batch and where its later publication verification is recorded.

The three added DMG p.74 matrix records preserve literal source cells and separate table notes, including the unresolved PHB p.30/DMG p.74 Monk conflict. Their complete-table crops have their own owner, crop, context, highlight and default assessments; those assessments do not review individual cell-to-field targets or the older global mapping queues. Supplemental DMG p.175 image coordinates remain separate from canonical-PDF coordinates in current audit generation, and PDF-only raster analysis retains an explicit unassessed image-source state.

Regenerate `node tools/source-completeness-coverage.mjs` after changing a ledger, the repair register or assembled data. Node tests reject missing books/pages, invalid folios/dispositions, lost source locators, mixed supplemental/PDF identities and stale committed report inputs. Unknown row/prose/profile/qualifier/continuation scopes remain explicit review work. Global excerpt/field mapping remains a separate follow-on task.
